# Agent-memory code review — 16 September 2026

The review covered durable memory, revision conflicts and history, MCP stdio,
the CLI, dashboard memory requests, and local service locking. Full workspace
checks also exercised the retained storage implementation. The branches keep
their distinct legacy storage code; shared memory fixes apply to both.

## Findings resolved

| Finding | Fix and regression coverage |
| --- | --- |
| Every memory connection acquired a write transaction and scanned all entries to backfill revision counters. A fresh reader failed after 10 seconds if another writer held the database. | Schema version 2 runs initialization/backfill once. A regression opens a new reader during an active write transaction and reads committed context successfully. |
| Concurrent first-time connections could fail while switching SQLite into WAL mode, even with a busy timeout. | Retry only SQLite `BUSY` initialization failures within a bounded deadline, with failed transactions rolled back. Four simultaneous initializers are covered by a test, repeated 20 times locally. |
| The dashboard rejected valid 64 KiB memories when JSON escaping exceeded its 128 KiB request limit. | Allow up to 512 KiB on the wire while retaining the store's 64 KiB content limit. Tests cover sixfold escape expansion and rejection of oversized content. This applies to the implemented `AI_coded` gateway. |
| CLI memory output panicked when a pipe reader exited early. | Propagate output errors to the existing broken-pipe handling; add equivalent handling on `main`. A subprocess regression closes stdout before consuming the memory. |
| Local services and benchmarks assumed a held OS file lock always reported `WouldBlock`, which is not portable to Windows. | Compare against the locking library's platform-specific contention error. Existing lifecycle tests cover duplicate instances and status/stop; the benchmark test now checks the intended conflict error. These services exist on `AI_coded`. |
| Publishing blocks renamed a directory while its data and metadata files were still open, which Windows rejected. | Close both files after syncing them and before renaming the directory. Storage and transfer regressions now pass on Windows. Native path-separator tests also cover platform differences. This applies to `AI_coded`. |
| `mammoth commands` rebuilt the large derived command tree inside backend dispatch and overflowed the Windows debug-build stack. | Reuse the tree built for argument parsing, including for shell completions. Command-list and color tests exercise this path; completion tests cover all five supported shells without creating a store. This applies to `AI_coded`. |

Unknown future database versions are now rejected before changing journal mode.
Upgrade tests preserve current entries, full history, search results, and revision
counters for deleted keys. CI also publishes test failure details in annotations
so platform-specific errors are easier to diagnose.

## Measured optimization

On this Apple Silicon Mac, a release-build CLI `memory get` against 10,000 entries
took a median **5.90 ms before** and **3.33 ms after** the change: about **43% less
elapsed time** for this workload. Each measurement uses 30 separate CLI processes
after five warm-up runs, including process startup and JSON output. This is a
local warm-cache measurement, not a general throughput or durability benchmark.

The larger improvement is removing work proportional to the number of entries
from every connection and allowing reads during an active writer transaction.
SQLite still permits one writer at a time.

## Local storage selection

An existing shell export selected a different store from the local test dashboard,
so `mammoth ls` showed a different namespace. Updating the export restored the
expected listing without moving any data. A subprocess regression verifies that
`ls` uses `MAMMOTH_LOCAL_ROOT`, that `--local-root` overrides it, and that the
listing contains stored directories rather than the host working directory.
The homepage and CLI guide on both branches explain this precedence, persistent
shell settings, and the distinction between file listings and memory recall.

## Upgrade note

Version 1 databases upgrade automatically in a transaction without discarding
memory. Stop older processes and update both the CLI and MCP server together:
older binaries reject a version 2 database. See the
[memory durability guide](../AGENT-MEMORY.md) for backup and upgrade details.
